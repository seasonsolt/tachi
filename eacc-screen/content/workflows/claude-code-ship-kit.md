## Problem

Many builders can get AI to generate code, but not to help them **ship consistently**. The missing piece is a loop that keeps discovery, implementation, and review separate enough to stay sane.

## Recommended stack

- `Claude Code` for repo-native implementation work.
- A lightweight issue list or weekly ops note for scoping.
- A publish checklist that ends with a measurable artifact: merged code, a route shipped, or a tracked CTA.

## The weekly loop

1. Start with one page or feature outcome, not a broad brainstorming prompt.
2. Capture acceptance checks before editing anything.
3. Let the agent implement the smallest viable diff.
4. Run tests, route checks, and one crawlability proof before calling it done.

## Failure modes

- Shipping a tool page with no workflow context.
- Letting the homepage become an art object instead of a discoverable asset.
- Treating ads as the monetization strategy instead of the fallback layer.

The page earns in three layers:

- **affiliate/referral** when the reader wants the exact build loop,
- **newsletter capture** when they want more workflows first,
- **ads** only as a supplemental slot.
